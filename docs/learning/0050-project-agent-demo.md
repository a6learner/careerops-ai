## 这次新增了什么

开发阶段的设计理由、失败和验证结果可以成为带来源的项目草稿。用户审核后，
另一个会话可按项目检索，辅助准备英文简历要点与中文面试材料。
这条路径使用用户代码助手已有的模型，CareerOps 不新增服务端模型调用。

当前形态是宿主驱动的 agent 扩展：模型根据目标和 Skill 选择、组合工具，
通过返回状态决定继续读取、保存或恢复。没有独立后台 planner，也不承诺自动记录每一步。

## 每一层负责什么

```text
用户目标与上传范围
  -> 代码助手宿主 + 模型 + Skill
  -> MCP stdio 工具 -> 本地 gateway/受保护状态
  -> CareerOps HTTP API -> service/repository -> PostgreSQL
用户网页审核 -> API -> 更新记录审核状态
新会话模型 -> MCP 检索/读取当前状态 -> 带引用的求职草稿
```

| 组件 | 实际职责 | 不应误解为 |
|---|---|---|
| Host（如 Codex） | 运行会话、提供模型和工具连接，执行其权限约束 | CareerOps 自己训练或托管的模型 |
| 模型 | 读选定材料、归纳、选择工具、生成草稿；可能出错 | 事实权威、测试认证者或个人贡献的确认人 |
| Skill | 规定何时记、记什么、如何找回和约束求职表达 | 常驻监听器或安全隔离机制 |
| MCP server | 发布有类型的工具，将调用交给现有 gateway，处理协议和安全错误 | 自动审批上传、直接操作数据库或执行任意代码的服务 |
| 本地 gateway/store | 终端登录后的凭证、受保护包与回执、账号绑定、同键重放 | 服务端事实源；DPAPI 也不能阻止同一 Windows 用户下的任意恶意代码 |
| API/service | 身份与所有权检查、输入验证、事务、审核和幂等语义 | 在这个新增记录路径中调用模型的组件 |
| PostgreSQL | 权威项目/来源/状态，CHECK、外键和不可变约束 | 与本地回执相互替代的缓存 |
| 现有 worker/Redis | 原有解析/分析工作流与可重建分发机制 | 本次 checkpoint 存储或宿主模型的必经路径 |

## 作者如何演示

先按照 [README 的当前运行说明](../../README.md)启动对应本地服务。
使用当前项目环境和[Codex 配置示例](../../integrations/mcp/codex.example.toml)，
替换占位路径，并保持终端登录与 MCP 的 API/state 设置一致。
示例文件不是安装器。不要把密码、token 或真实私人配置粘入对话、Skill 或 MCP 参数。
用户在自己的交互终端执行 `<python> -m careerops.agent login`。

现场应使用明确标识的合成项目和隔离账号/状态；若使用自有项目，先限定实际允许读取和上传的摘录。
本次授权的两次真实 Codex 模型会话已使用；下面保留复现步骤，后续真实模型运行需另行授权。
启动失败与实际进入模型的会话分开记录，不能用进程启动次数代替模型会话数，
也不能由会话数推导底层 provider 请求次数。

1. **第一会话：保存一个阶段。** 指定一个实际存在的 Project UUID，并提供少量选定来源。
   让宿主调用工具保存草稿，现场核对 `packet_id`、record ID、`status` 和内容摘要。
   只有拿到 accepted 回执才说 API 已接受；pending 表示仍须恢复。
2. **网页人工审核。** 查看来源摘录、验证条件、AI 参与与个人贡献；显式填写负责范围后确认。
   合成项目必须保留“演示材料”的标签，确认行为不能把它变成真实履历。
3. **第二个新会话：找回与讲述。** 提供同一个 Project UUID 和目标要求，要求先搜索已确认记录，
   再读取支撑每项说法的详细来源，生成英文简历候选句和中文面试讲述。
   没有 JD 时生成通用材料并标明尚未按岗位定制。新会话不依赖第一会话聊天历史。
4. **检查撤回语义。** 用户可以在网页撤回记录；随后确认当前查询不会继续将其作为正向依据。
   超过本次模型运行预算时，这项通过已有 API/工具确定性检查或后续单独授权验收，
   不暗中开启第三次模型运行。

第一会话可使用这样的提示词，先把占位内容换成真实范围：

> 使用 careerops-project-journal Skill。仅依据我提供的选定材料，向项目 `<project-uuid>`
> 保存一个阶段草稿。我授权上传这些摘录，不上传其他文件。记录问题、行动、取舍、
> 失败、实际验证、未验证项和贡献待确认事项；使用稳定 UUID 幂等键。
> 这是合成演示，不是真实个人经历。报告工具回执和审核状态，不自动确认。

第二会话可使用：

> 回顾项目 `<project-uuid>`。先取项目上下文、搜索已确认记录并读详细来源，再给出
> 两条英文简历草稿与中文面试讲述。每项事实注明 record ID 和 source locator；
> 严格区分系统实现、我的确认贡献和缺失证据。不得补造指标。合成演示材料不能作为真实履历。

## 演示中需要观察的失败路径

- **LOGIN_REQUIRED：** 保留原包与键，让用户回终端登录，再重放；不在聊天索要密码。
- **pending / 没有回执：** 写入可能已成功；使用原 `packet_id` 重放相同内容，不能换键“再保存一次”。
- **rejected / 冲突 / 账号不匹配：** 停止并解释，不能修改原包来绕过失败。
- **草稿、撤回或缺少来源：** 只能说明历史或缺口，不能生成当前正向求职结论。
- **模型声称工具成功：** 查真实调用轨迹、回执与 API 状态；模型文字本身不是持久化证据。


启动服务本身不会再次调用真实模型。删除数据库卷是另外的破坏性操作，不在这两条命令中。

本次没有现场演示丢失回执后的重放或撤回后的再次模型召回；相关确定性测试与本次现场结果分开。

## 必须理解的概念

Level 1：解释模型决策与后端可靠性如何分工、凭证与所有权边界、事务不确定性、
幂等键与内容摘要的区别、来源校验与真实性的区别、人工确认与能力认证的区别。

Level 2：能沿 `mcp_server.py -> gateway.py -> client.py -> API` 跟踪一次保存，
解释为什么先保存受保护包、为什么错误需脱敏、为什么读取证据前要取当前审核状态，
并能按 README 启动与排查本地连接。
